# PubSub

Краткое описание:
- Поддерживает подписку/отписку, закрытие
- Graceful shutdown
- Логирование через `log/slog`
- Можно безопасно конкурентно много раз закрывать `PubSub`, отписываться от событий, вызывать `Publish/Subscribe` на закрытом `PubSub`
- Api по Grpc
- Тестирование grpc хэндлеров (с ипользованием моков) и сервиса (pubsub)

---

## Как работает
### Подписка
`Subscribe(subject, cb)`:
- Создаётся `subscriptionImpl` с двумя каналами:
   - `messages` (buffered, размер `queueSize`)
   - `stream` (unbuffered)
- Добавляем подписку в `data[subject]` под блокировкой.
- Запускаем две горутины:
   - Первая (функция `start`):
     - Читает из канала `messages`, кладет сообщения `buffer`, либо отправляет сообщения в `stream`.
     - При `close(messages)` выгребает остаток, логирует и закрывает `stream`.
     - Благодаря такому подходу, даже если подписчик медленный, публикатор долго ждать не будет (даже если канал переполнен), так как из канала `messages` сообщения будут попадать в буфер.
   - Вторая: читает из стрима (`for msg := range stream`), вызывает `cb(msg)`.
- Увеличиваем `sync.WaitGroup` на 2, чтобы в close подождать завершение всех воркеров.

### Публикация
Метод `Publish(subject, msg)`:
- Для каждой подписки (все проиcходит под r-блокировкой, `rlock`) вызывает `send(msg)`, где проверяет флаг `unsubscribed` и отправляет в `messages` сообщение.
- Если `Close` уже вызван, возвращает `ErrSubPubAlreadyClosed`.

### Отписка
`Unsubscribe()`:
- Под эксклюзивной блокировкой меняет флаг `unsubscribed` и закрывает канал `messages`.
- После закрытия канала `messages` функция `start` догребает остаток из `messages`, закрывает `stream` и завершается, тем самым 2 горутины корректно завершаются.

### Закрытие
`Close(ctx)`:
- Под блокировкой проверяет и выставляет меняет `closed`, также вызывает `Unsubscribe()` для всех подписок.
- Запускает горутину, которая ждёт `wg.Wait()` (для завершения всех горутин).
- В `select` блокируется: `<-done`, `ctx.Done()`.
- После закрытия, методы `Publish` и `Subscribe` вернут ошибку.

## Конфигурация

```yaml
grpc_port: 0.0.0.0:50051 //по умолчанию :50051
queue_size: 256 //размер канала, в который отпрявляет сообщения публикатор (если не указывать, то 256)
log_level: debug //по умолчанию INFO
```

## Запуск

- Собрать докер образ:
    ```bash
    $ docker build -t pubsub:latest .
    ```
- Запустить контейнер:
    ```bash
    $ docker run --rm -p 50051:50051 -v ./config:/app/config -e CONFIG_PATH=./config/local.yaml pubsub:latest
    ```
- Либо если установлен `task` (https://taskfile.dev), то:
    ```bash
    $ task docker-build
    $ task docker-run
    ```
